# DTR-8531: controlling body name screens

The name screens use one controller and two views, with the existing business-name
and sole-proprietor forms and English/Welsh messages. Existing names are prefilled;
missing names are left blank. Continue validates and saves the name in the session.
Back uses the standard browser-back link.

The views take typed forms and derive the business-name heading and title from
the business type. The controller supplies the data; it does not pass duplicate
message keys or unused view-mode arguments.

## Routes and session data

GET and POST routes share the prefix
`/change-registration-details/controlling-body-details/` and the following suffixes:

| Business type | Suffix |
| --- | --- |
| Sole proprietor | `sole-proprietor` |
| Partnership | `partnership` |
| Corporate body | `corporate-body` |
| Unincorporated body | `unincorporated-body` |
| Limited liability partnership | `limited-liability-partnership` |

The name and trading-name-screener controllers use
`ControllingBodyNameDataRequiredAction`. On the first visit this calls I1.36 at
`/gambling/controlling-body-details/mgd/:mgdRegNumber`, using the authenticated
registration number. It maps `typeOfControllingBody`, `businessName`, and the sole
proprietor fields into the session, then marks the section as loaded. Subsequent
visits reuse the cache. Names already edited in the session are preserved during
initial loading, including when the business type was cached before the name.

The name pages store `businessName`, `soleProprietor`, `loaded`, and
`addTradingName` under `controllingBodyDetails`. Business type uses the existing
`controllingBodyDetailsSection.typeOfControllingBody` page and numeric
`BusinessType` format, so a type selected in the business-type screen is retained.
Sole proprietor uses `SoleProprietorName`. The existing full-section loader,
`ControllingBodyDetailsDataRequiredAction`, remains available to the business-type
screen; the name loader has a separate loaded marker so it still fetches names
when only the business type is cached.
Registered-business and partner data remain separate. Backend/cache failures,
missing or invalid business types, and URLs inconsistent with the cached type
redirect to the service-error page. A successful response without a name leaves
the name input blank.

## Navigation

Continue from the partnership, corporate-body, unincorporated-body and LLP name
screens saves the name and opens **CB-TN-SC** at
`/change-registration-details/controlling-body-details/trading-name-yes-no`.
The screener renders the specified question, Yes/No options, Back and Continue,
validates the selection, and saves it in the controlling-body cache.

The later screens after the trading-name screener (CB-TN and the business-type
identity screens) remain separate journey work; the screener's onward navigation
currently uses the repository's Index placeholder. The sole-proprietor name's
CB-DOB/CB-CYA destination and the registration summary's controlling-body entry
link also remain integration dependencies. The new screener's Welsh message keys
use the repository's `cy:` placeholder convention pending translated copy.

## Specification decisions

- The ticket's partner-index note appears inherited from its cloned partner
  ticket. The five screen specifications use unindexed URLs, and
  [I1.36](https://confluence.tools.tax.service.gov.uk/spaces/RBD/pages/1369407855/I1.36-+Get+Controlling+Body+Details)
  returns a single controlling body. This implementation follows those contracts.
- [CB-BN-PS](https://confluence.tools.tax.service.gov.uk/spaces/RBD/pages/1373439134/CB-BN-PS+-+Change+partnership+name)
  specifies a 35-character partnership-name error but a 160-character limit in
  its developer table. The implementation follows the user-facing requirement
  and existing shared form: 35 for partnerships, 160 for other business names.
  Partnership names accept letters, digits, ampersands, apostrophes, round
  brackets, commas, exclamation marks, hyphens, slashes and spaces. Full stops
  are rejected to match the supplied error copy.
- The sole-proprietor screen includes the registration-details caption in its
  page title, as specified, and supports an optional middle name. The shared form
  now also treats whitespace-only middle names as absent; its regression tests
  bind complete valid names so an unrelated required-field error cannot hide a
  failure of this optional-field behaviour.

## Verification

The name-journey tests cover partnership, corporate body, unincorporated body and
LLP. Each starts without cached data, calls a stubbed I1.36 HTTP endpoint through
the real connector, displays the backend name, rejects a name containing a full
stop, saves a valid edit, follows the real navigator to CB-TN-SC, and revisits the
name screen to verify that the edit is retained without another backend request.

Additional tests cover all five business types, blank and partial names, cache
preservation, backend/cache failures, permitted partnership characters and length
boundaries, and the trading-name screener's rendering, validation and saving.

After resolving the rebase conflicts on 30 September 2026, all 2,795 unit tests
and 11 database integration tests passed, with one pre-existing ignored test.
Formatting checks passed. The tests cover both controlling-body loaders, the
existing business-type screen, and preserving a selected business type when it
differs from the backend value. Cache and save-result handling in the name journey
use pattern matching.
